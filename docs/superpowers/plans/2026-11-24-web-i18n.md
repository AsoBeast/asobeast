# Web internationalization implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add English and Simplified Chinese to every first-party web surface, with browser based default language and a remembered manual choice, without changing URLs or API contracts.

**Architecture:** Use `next-intl` 4.16.0 without locale based routing. Resolve `en` or `zh-CN` from the `asobeast_locale` cookie, then `Accept-Language`, then English. Load feature namespaced JSON catalogs on the server, provide them to Client Components, and switch language by writing the cookie followed by a full navigation to the same URL.

**Tech Stack:** Next.js 16.4.5 App Router, React 19, TypeScript strict, `next-intl`, Vitest, Playwright, existing Tailwind and shadcn components.

**Spec:** `docs/superpowers/specs/2026-11-24-web-i18n-design.md`

## Global Constraints

- Supported locales are exactly `en` and `zh-CN`.
- The locale cookie is named `asobeast_locale`, uses `SameSite=Lax`, `Path=/`, and lasts one year.
- URLs, query parameters, API paths, shared contract types, MCP tools and database schema do not change.
- No Server Actions and no `router.refresh()`.
- Dates stay UTC. Storefront names use static dictionaries, not `Intl.DisplayNames`.
- Store prices keep `en-US` currency formatting and existing fraction rules.
- Store supplied content and user written content remain untranslated.
- Swagger UI, Bull Board, Mintlify docs, marketing pages and emails remain out of scope.
- Stripe Checkout remains `locale: 'en'`.
- Billing sentences remain owned by `lib/plan-choice.ts`, `lib/order-summary.ts`, `lib/paywall-faq.ts` and `planRenewalTerms`.
- No comments in source or tests.
- Every visible feature gets a plain-language What's New entry in the same pull request.

## Review Focus

- An invalid or unsupported locale cookie must fall back safely and must never become a dynamic import path. Task 1 pins cookie validation and locale precedence.
- A Chinese browser on first visit must see Chinese sign-in, while an explicit English choice must survive reload. Task 3 and Task 6 pin this in Playwright.
- Switching language on a deep link must preserve path, query string and hash. Task 3 pins the same-URL navigation helper.
- Dates, country names, relative times and number formatting must hydrate identically in Chromium and WebKit. Task 4 and Task 12 pin both engines.
- Missing Chinese keys, invalid ICU messages and unmapped common API failures must not silently ship. Task 2 and Task 11 make these failures visible in CI or localize the fallback.
