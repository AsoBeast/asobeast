Every variable below is read by the API from `apps/api/.env`, or from the environment of the API container. Everything except `DATABASE_URL` and `AUTH_SECRET` has a working default.

<Warning>
  Three settings stop a deployment cold. `AUTH_SECRET` must be at least 32 characters or the API refuses to boot, and changing it signs out every user. Compose refuses to start when `POSTGRES_PASSWORD` or `AUTH_SECRET` is missing or empty from the root `.env`.
</Warning>

## Required

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `DATABASE_URL` | `postgresql://asobeast:asobeast@localhost:5433/asobeast` | Yes | PostgreSQL connection string. Compose sets it from `POSTGRES_PASSWORD` |
| `AUTH_SECRET` | None | Yes | Signs session cookies. At least 32 characters. Generate with `openssl rand -hex 32` |

## Core

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `REDIS_HOST` | `localhost` | No | Host holding the BullMQ queues |
| `REDIS_PORT` | `6380` | No | Redis port |
| `REDIS_DB` | `0` | No | Redis database index for the queues. The end to end suite uses a separate index |
| `PORT` | `4000` | No | Port the API listens on |
| `DEFAULT_COUNTRY` | `us` | No | Home storefront used when an import URL carries no country segment |
| `LOG_LEVEL` | `debug`, and `log` in the Compose stack | No | One of `error`, `warn`, `log`, `debug`, `verbose`. Logs are JSON in production and human readable in development, and every line inside a request or job carries its workspace and correlation id. Compose lowers it to `log` because `debug` records every request, and container logs rotate at 10 MB across 3 files |
| `ACCOUNT_DELETION_GRACE_DAYS` | `7` | No | Days a scheduled workspace deletion stays reversible. The retention job erases the workspace on the first run after the grace period ends |
| `ERROR_TRACKING_DSN` | Empty | No | Sentry dsn for scrubbed error reports. Ignored unless `NODE_ENV` is `production` **and** `BILLING_ENABLED` is `true`, so a self hosted deployment never reports its errors to anyone else. Reports carry the error type, a secret scrubbed message and stack, the workspace and correlation id, and the request method with identifiers masked out of the path. They never carry headers, cookies, query strings, request bodies or account details. See [Hosted observability](/operations/hosted-observability#error-reporting) |

## Scheduling

Every cron expression is evaluated in UTC. See [The daily pipeline and rate limits](/concepts/pipeline).

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `CRON_DAILY` | `0 3 * * *` | No | Starts the daily pipeline. Batched alerts flush after its processing completes, not on a clock |
| `CRON_SCORING` | `0 4 * * 0` | No | Recomputes traffic and difficulty weekly on Sunday |
| `CRON_RETENTION` | `0 5 * * *` | No | Prunes rows past their retention window |
| `CRON_AUDIT` | `0 6 * * *` | No | Writes the daily audit score snapshot |
| `CRON_DIGEST` | `0 8 * * 1` | No | Sends the weekly digest webhook on Monday |
| `CRON_PROXY_SYNC` | `0 2 * * *` | No | Reconciles the egress proxy pool against the provider. Never scheduled while `PROXY_PROVIDER` is `none` |
| `CRON_STORE_CANARY` | `0 2,8,14,20 * * *` | No | Asks each store whether it still parses, one hour before the daily run so the day's first collection meets a known state. An empty value removes the schedule and switches the canary off. See [Recover from a broken store parser](/operations/scraper-breakage) |

## Collection rate limits

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `SCRAPE_ITUNES_RPM` | `15` | No | iTunes requests per minute. The App Store worker runs concurrency 1 behind this limiter |
| `SCRAPE_GPLAY_RPM` | `10` | No | Google Play job starts per minute, not requests, because one job fans out to many |

Raising either value risks the host IP address being throttled by the store. See [The daily pipeline and rate limits](/concepts/pipeline).

## Egress proxy pool

Optional. With `PROXY_PROVIDER` left at `none` every store request leaves from the host address, which is what a self hosted instance wants. Point it at a provider only when one address cannot carry the collection volume.

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `PROXY_PROVIDER` | `none` | No | `none` disables the pool. `webshare` reconciles the pool against that account's proxy list |
| `PROXY_API_URL` | `https://proxy.webshare.io/api/v2` | No | Provider API base URL |
| `PROXY_API_KEY` | Empty | When a provider is set | Provider API key. The API refuses to boot when a provider is configured without one |
| `PROXY_USERNAME` | Empty | No | Credentials shared across the pool. Leave empty for an IP authorized account |
| `PROXY_PASSWORD` | Empty | No | Password for `PROXY_USERNAME` |
| `PROXY_ENDPOINT_RPM` | `15` | No | Requests per minute allowed per pool endpoint. This is the limiter that replaces the single host budget once the pool is on |
| `PROXY_ACQUIRE_TIMEOUT_MS` | `120000` | No | How long a job waits for a free endpoint. A saturated pool delays work rather than dropping it, and only fails once this budget runs out so the queue can retry with backoff. A shutdown ends the wait at once, so the budget never holds up a drain |
| `PROXY_WORKER_MAX_CONCURRENCY` | `8` | No | Ceiling for store worker concurrency once the pool is on. Actual concurrency tracks the healthy endpoint count and falls back as endpoints cool down. Ignored while `PROXY_PROVIDER` is `none` |

With `PROXY_PROVIDER` at `none` the store workers keep concurrency 1 behind `SCRAPE_ITUNES_RPM` and `SCRAPE_GPLAY_RPM`. Those two variables never change meaning: they describe the budget of a single egress address, which is exactly what a self hosted instance has.

Credentials stay in configuration. The database records only which credential a pool endpoint uses, never the secret itself.

### Residential fallback

Datacenter addresses carry the traffic. A residential gateway is an emergency path for a single request that a datacenter address was blocked on, never a primary route, because residential bandwidth is metered and costs orders of magnitude more per request.

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `PROXY_RESIDENTIAL_URL` | Empty | No | Gateway used only after a datacenter address is blocked. Empty disables the fallback |
| `PROXY_RESIDENTIAL_USERNAME` | Empty | No | Gateway credentials |
| `PROXY_RESIDENTIAL_PASSWORD` | Empty | No | Password for `PROXY_RESIDENTIAL_USERNAME` |
| `PROXY_RESIDENTIAL_MONTHLY_CAP_USD` | `0` | No | Hard monthly ceiling. Every residential request is claimed against it before it leaves, so a job that fans out to many requests stops at the ceiling rather than crossing it. At `0` every fallback is refused, so a broad block cannot turn into an unbounded bill |
| `PROXY_RESIDENTIAL_COST_PER_GB` | `3` | No | Provider list price, used to price the cap |
| `PROXY_RESIDENTIAL_MB_PER_REQUEST` | `1.2` | No | Measured average response size. With the price per gigabyte this estimates month to date spend |
| `SIGNUP_CAPACITY_MAX_UTILIZATION` | `0` | No | `0` disables the gate. Above `0`, registration is refused with `503` once tracked collection passes this share of daily capacity. Applied only when `BILLING_ENABLED` is `true`, so a self hosted instance is never gated |

## Alerts

See [Send alerts](/guides/alerts).

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `ALERT_DELIVERY` | `batched` | No | `batched` sends up to two scoped reports per channel after daily processing completes. `instant` sends one notification per event. Warns in production when `instant` has no SMTP configured. Webhook subscriptions live in the database, so configuration validation cannot see them |
| `ALERT_RANK_DROP_THRESHOLD` | `5` | No | Positions a primary app must move before a rank alert fires |
| `ALERT_REVIEW_SCORE_MAX` | `2` | No | Highest star rating treated as a negative review. Accepts 1 to 4 |
| `ALERT_ACTIONS_MIN_PRIORITY` | `high` | No | Lowest priority that fires `action.opened`. One of `critical`, `high`, `medium`, `low` |
| `WEBHOOK_ALLOW_PRIVATE_TARGETS` | `false` | No | `false` keeps alert webhooks on public addresses. Loopback, private, carrier grade NAT, link local and cloud metadata targets are refused when the webhook is registered and again when the connection is made, so a hostname that resolves to an internal address cannot reach it either. `true` opts a self hosted instance in to delivery on its own network. Refuses to boot when `true` with `BILLING_ENABLED` set to `true`, because the url belongs to the customer, and warns in production otherwise |
| `WEB_PUBLIC_URL` | Empty | No | Public web origin, `http` or `https` only, and any other scheme refuses to boot. Builds deep links inside alert payloads, the Stripe return address and the email confirmation and recovery links, and is the single origin CORS allows. Unset leaves an alert link `null`, closes checkout, sends no CORS headers, refuses account recovery with `503` because its link would carry no host, and refuses to boot when `BILLING_ENABLED` is `true` with SMTP configured, because confirmation is mandatory there |

## Email delivery

Email stays disabled until both `SMTP_HOST` and `SMTP_FROM` are set.

Email is optional on a self hosted instance and mandatory on a metered one. With `BILLING_ENABLED=true` in production and no mail path, the API warns at boot that it can confirm no address, warn nobody before a trial ends, and recover no forgotten password. See [Hosting behind TLS and a reverse proxy](/security/hosting).

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `SMTP_HOST` | Empty | No | SMTP server host. Required to enable email |
| `SMTP_PORT` | `587` | No | Use `465` with `SMTP_SECURE=true`, otherwise 587 or 25 |
| `SMTP_SECURE` | `false` | No | `true` wraps the connection in TLS from the start, which port 465 expects. Warns in production when `true` on any other port |
| `SMTP_USER` | Empty | No | Leave empty for an unauthenticated relay |
| `SMTP_PASSWORD` | Empty | No | Paired with `SMTP_USER` |
| `SMTP_FROM` | Empty | No | From address such as `asobeast <alerts@example.com>`. Required to enable email |

| `AUTH_REGISTRATION_WORKSPACE` | `own` | No | Where a self registration lands. `own` gives every sign up a workspace of its own, so someone who registers never sees the apps, keywords and rankings already tracked on the instance. `shared` puts every sign up in the bootstrap workspace as a member, which suits an instance whose sign ups are all trusted with that data. | `STRIPE_PORTAL_RETURN_URL` | empty | No | Where the customer portal returns to. Falls back to `WEB_PUBLIC_URL` plus `/settings` |
| `STRIPE_PRICE_INDIE_MONTHLY` | empty | No | Price id for Indie monthly. Create the catalog with `pnpm --filter api stripe:catalog` |
| `STRIPE_PRICE_INDIE_YEARLY` | empty | No | Price id for Indie annual |

| `STRIPE_PRICE_ULTIMATE_YEARLY` | empty | No | Price id for Ultimate annual |
| `CRON_BILLING_RECONCILE` | `0 7 * * *` | No | Daily reconciliation of local subscription state against Stripe, UTC |
| `CRON_TRIAL_NOTICES` | `0 9 * * *` | No | Daily sweep that sends the trial milestone emails, UTC |
| `AUTH_COOKIE_SECURE` | `false` | No | Marks the session cookie `Secure`. **Refuses to boot** when `false` and `NODE_ENV` is `production`. The Docker image sets `NODE_ENV=production`, so the Compose stack defaults this to `true` |
| `TRUST_PROXY` | `0`, and `1` pinned in the Compose stack | No | How many proxies you control sit between the internet and the API, counting the web app as one. Compose pins it to `1` because the web app is always exactly one hop in front of the API there. `true` means 1 and `false` means 0. The API reads that many entries back from the right of `X-Forwarded-For`, so auth throttling keys on the real client address. Both apps warn at startup in production when `0`. ## Published store status

An opt-in outbound integration, off by default. When `STORE_STATUS_URL` is empty **no request is ever made** and the poll is not even scheduled. See [What leaves your deployment](/legal/data-collection) and [Recover from a broken store parser](/operations/scraper-breakage).

| Variable | Default | Required | Effect |
| --- | --- | --- | --- |
| `STORE_STATUS_URL` | Empty | No | Url of a published store status document. Setting it opts this deployment in to an hourly bare `GET` of that url, so a store breakage the maintainer already knows about can be announced without waiting for the local canary. Empty means no request is ever made. Give the final url: a redirect is not followed |
| `CRON_STORE_STATUS` | `17 * * * *` | No | When the poll runs, UTC. The odd minute is deliberate, so installations do not all arrive at the top of the hour. Never scheduled while `STORE_STATUS_URL` is empty |

The poll goes through the same public only address guard that alert webhooks use, so a url resolving to a loopback, private, link local or cloud metadata address is refused at both configuration and connection time. A failed or stale poll never changes what the local canary reported.

## Retired variables

`BULL_BOARD_USER` and `BULL_BOARD_PASSWORD` are ignored. The queue dashboard now requires an owner session or a personal API token instead of basic authentication, and the API logs a warning at boot if either variable is still set. Remove them.

## Keeping this page correct

This page and the `.env.example` files change in the same commit. If a default here disagrees with `apps/api/.env.example`, the file is right and this page is a bug.
