AI in asobeast is garnish, not foundation. Every score, rule and recommendation is deterministic and works with no key configured, which is the default.

## What does the key enable?

Five features, all bring your own key.

| Feature | Where | What it does |
| --- | --- | --- |
| AI creative analysis | Audit tab | Reads the icon, up to six screenshots and up to five competitor icons, and reports captions, caption language, message type, text in the icon, element count, contrast and similarity to a competitor icon. The audit rules score what it reports |
| Metadata drafts | Metadata workbench | Proposes field values grounded in your tracked keywords, coverage gaps and competitor titles, for the primary listing or for an additional language one of your storefronts reads |
| Action explanations | Action card | Turns typed evidence into two to four plain sentences |
| Review reply drafts | Reviews page | Drafts the developer reply to one review in its language, in the tone you pick and within the store's limit, following the app's reply guidelines |
| Review translations | Reviews page | Translates the title and text of one review into your browser's language and keeps the translation on the review |

Each feature is a single completion per run. The creative analysis runs in the background after you start it, so leaving the page does not cancel it. It is reused while the icon, the screenshots, the competitor icons and `AI_MODEL` are unchanged, so analyzing an unchanged listing again costs nothing, and a finished analysis records today's audit score. The nightly score snapshot reads the stored observations and never calls the model.

## How many AI calls can a workspace make?

Every AI call spends one call from a monthly allowance that the whole workspace shares. The allowance of each plan is listed on [Pricing](/legal/pricing#rate-limits). It renews at 00:00 UTC on the 1st of every month, and unused calls do not carry over.

| Counts as one call | Costs nothing |
| --- | --- |
| Explaining an action, including Regenerate | A creative analysis of a listing that has not changed since the last one |
| One set of metadata drafts | Starting an analysis while one is already queued or running |
| One creative analysis | A request refused before it reaches the model, such as an unsupported field |
| One review reply draft, including Draft again | A reply you write by hand, copy or mark |
| One review translation | Showing a translation already kept for the same language |
| An answer the model gave that could not be used, such as a refusal or an incomplete set of drafts | A call the provider never answered: a timeout, an outage, a rejected key |

Two clicks on the same button while the first is still working spend one call. A creative analysis that retries in the background is still one call.

The settings page shows the calls used this month and the renewal date, and every AI button shows how many are left. When none are left the buttons are disabled until the 1st, and the API answers `429` with an `aiAllowance` object; see [Errors](/api-reference/errors#a-spent-ai-allowance).

Upgrading applies the larger allowance at once and keeps what was already used. Moving to a smaller plan keeps the usage too, so a workspace already past the smaller allowance waits for the 1st.

### Self hosted

A self hosted instance has no allowance unless you set `AI_CALLS_PER_MONTH`, which applies to every workspace on the instance. Set it if registration is open, because each account that registers gets a workspace of its own and spends your provider key. See [Configuration](/configuration/reference).

## What happens without a key?

The product is fully usable. Precisely four things differ.

| Surface | With no key |
| --- | --- |
| AI endpoints | Answer `409` |
| Metadata drafts card | Hidden |
| Audit tab | Shows a one line setup hint instead of the analyze button |
| Reply composer | Works without AI. The Draft with AI button and the reply guidelines are hidden |

Every other audit check still scores. The creative checks are listed as unanswered rather than guessed, and the audit weights each factor by how much of it was measured, so they neither raise nor lower the score. See [Run an ASO audit](/guides/aso-audit).

## Configure it

| Variable | Default | Notes |
| --- | --- | --- |
| `OPENAI_API_KEY` | Empty | Empty disables all four features |
| `OPENAI_BASE_URL` | Empty | Address of an OpenAI compatible API to call instead of OpenAI. Empty uses `https://api.openai.com/v1`. See [Use an OpenAI compatible provider](#use-an-openai-compatible-provider) |
| `AI_MODEL` | `gpt-5.6-luna` | The model name as your provider spells it. Must accept image input and structured outputs, because the creative analysis reads images and answers in a fixed schema. `gpt-4o` also qualifies |
| `AI_CALLS_PER_MONTH` | Empty | Calls each workspace may make per month on a self hosted instance. Empty is unlimited |

All four live in `apps/api/.env`. Restart the API after changing them.

## Use an OpenAI compatible provider

Set `OPENAI_BASE_URL` to the address of any API that speaks OpenAI's chat completions protocol, such as OpenRouter, a gateway like LiteLLM, or a model server on your own machine. Everything else stays the same: the key goes in `OPENAI_API_KEY`, the model in `AI_MODEL` exactly as the provider names it, and every call spends the same allowance. Restart the API after changing them.

```bash
OPENAI_BASE_URL=https://openrouter.ai/api/v1
OPENAI_API_KEY=sk-or-v1-your-key
AI_MODEL=openai/gpt-5.6-luna
```

The address must start with `http://` or `https://` and must not contain a user name, a password or a `#` fragment. The API refuses to start otherwise and names the variable. Use `https` for any provider outside your own machine, because the key and every prompt travel in the request.

The same variable reaches OpenAI's own regional hosts. `https://eu.api.openai.com/v1` keeps processing in the European Union for a key from an EU project, and asobeast still treats it as OpenAI.

### What the provider has to support

| Requirement | Needed by | When it is missing |
| --- | --- | --- |
| `POST /chat/completions` with a `system` and a `user` message and a bearer key | every feature | the call fails with the provider's own error |
| `response_format` of type `json_schema` with `strict: true`, answered as JSON that matches the schema | every feature | an answer that does not match is reported as unusable and still counts as one call, as it does on OpenAI |
| `image_url` parts with a public `https` address, which the provider downloads itself | the creative analysis only | the creative analysis fails. Drafts, explanations, replies and translations still work |
| `max_completion_tokens` | every feature | a provider that ignores it uses its own output limit, and a cut answer reads "The model ran out of output tokens." |

### How common providers fit

These notes follow each provider's own documentation. Check it for the model you pick, because support often varies by model rather than by provider.

| Provider | `OPENAI_BASE_URL` | Notes |
| --- | --- | --- |
| OpenRouter | `https://openrouter.ai/api/v1` | Models are named `vendor/model`. Pick a model that lists structured outputs and image input |
| Ollama | `http://host.docker.internal:11434/v1` from the Compose stacks, `http://localhost:11434/v1` from `pnpm dev` | Any non empty `OPENAI_API_KEY`, such as `ollama`. Ollama accepts images only as embedded data, so the creative analysis does not run. Small models often fail the schema |
| LM Studio | `http://host.docker.internal:1234/v1` from the Compose stacks | Any non empty `OPENAI_API_KEY`. Structured outputs are enforced by its grammar |
| vLLM | `http://your-host:8000/v1` | The server downloads images itself. If it runs with `--allowed-media-domains`, allow the store image hosts |
| LiteLLM proxy | `http://your-host:4000` | Set `drop_params: true` if a backend refuses a parameter LiteLLM forwards |
| Groq | `https://api.groq.com/openai/v1` | Strict structured outputs are enforced on a few models only |
| Azure OpenAI | `https://your-resource.openai.azure.com/openai/v1/` | `AI_MODEL` is the deployment name |

Anthropic's OpenAI compatibility endpoint for Claude (`https://api.anthropic.com/v1/`) ignores `response_format`, so Claude never sees the schema and its answers often fail the check. Anthropic also describes that endpoint as a way to test models, not a production path. DeepSeek's API offers JSON mode but not a JSON schema, so its answers often fail the schema check. The Gemini OpenAI compatibility layer documents images only as embedded data, so the creative analysis does not run there.

### Reaching a model on the Docker host

Inside the Compose stacks `localhost` is the API container itself, not your machine. Docker Desktop on macOS and Windows resolves `host.docker.internal` to the host. On Linux, add the name in a `docker-compose.override.yml` next to `docker-compose.yml`:

```yaml
services:
  api:
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

Make the model server listen on an address the container can reach. For Ollama that is `OLLAMA_HOST=0.0.0.0`.

### What the interface says

The audit's note under **Analyze creative** says the image links go to OpenAI when the address is OpenAI's, and to "the AI provider this instance is configured with" otherwise, so nobody reading it learns your provider's address. Error messages follow the same rule.

## What is AI never allowed to do?

It may only summarize an action that already exists. It can never create, rank, re order or suppress one, and the explanation prompt is told it may not change the recommendation.

The stored summary is labelled as an AI summary of deterministic evidence, so a reader can always tell which part of the card is computed and which part is prose. See [Work the Action Center](/guides/action-center).

A review reply draft is a suggestion the composer holds until you copy it, and the kept reply records that it came from the model.

Metadata drafts are constrained the same way. Every draft is linted again on the server and clamped to the store field limit, and asobeast has no write path to the stores, so a draft ends at a copy button rather than being published.

## What data leaves your deployment?

<Warning>
  Setting `OPENAI_API_KEY` sends data to OpenAI, or to the provider `OPENAI_BASE_URL` names. Only the app being worked on is sent, plus the public icons of its competitors for the creative analysis. Never other workspaces' data, never review text in the action explanation prompt, and never secrets. With the key unset, no request leaves your deployment for any AI feature.
</Warning>

The creative analysis sends the least data that answers its checks.

| Sent | Not sent |
| --- | --- |
| Store name, market code and title | Description, subtitle, short description and release notes |
| URLs of the app icon and up to six screenshots | Ratings, reviews, keywords and rankings |
| URLs of up to five competitor icons | Anything about other workspaces |
|  | The provider key, in any message or log |

The provider downloads the images from the store CDNs itself; asobeast never proxies image bytes. Competitor icon URLs are public store assets.

The action explanation prompt receives the app's store, country and title, the rule, the priority, the impact and the evidence object, and nothing else.

The metadata draft prompt receives the store, the listing's current metadata, up to 25 tracked keywords of the home market with their scores and coverage, competitor titles and your instructions. A draft for an additional language also sends the language and the codes of your markets that read it.

The review translation prompt receives the target language and the title and text of the one review being translated, and nothing else.

The review reply prompt receives the store, the app name, the one review being answered (its score, title, text, version, date, author and the developer reply Google Play shows), the listing's current version and release notes, the app's reply guidelines, up to three of the app's most recent Google Play replies as examples of your voice, the tone and your instruction line. Never another review and never other workspaces' data.

## Troubleshooting

- **The AI endpoints answer 409.** No key is configured, or the API was not restarted after setting it.
- **The audit button is missing but the key is set.** Confirm the key reached the API container. `docker compose config` shows the resolved environment.
- **The model rejects the request.** `AI_MODEL` must accept images and structured outputs. A text only model fails the creative analysis while drafts still work.
- **The API refuses to start and names OPENAI_BASE_URL.** The address is not an http or https URL, or it contains a user name, a password or a `#` fragment. Put the key in `OPENAI_API_KEY` instead.
- **Every call reports that the provider does not offer the model.** `AI_MODEL` still holds an OpenAI model name. Set it to the name your provider uses.
- **Could not reach the AI provider.** The API container cannot open the address. From the Compose stacks, `localhost` is the container; see [Reaching a model on the Docker host](#reaching-a-model-on-the-docker-host).

A failed creative analysis shows one of these messages. With `OPENAI_BASE_URL` naming a provider other than OpenAI, each message says "the AI provider" where it says "OpenAI" here, and "The OpenAI key" reads "The API key". Only transient failures are retried, once.

| Message | Fix |
| --- | --- |
| OpenAI rejected the API key. Check OPENAI_API_KEY. | Set a valid key and restart the API |
| The OpenAI key cannot use the model | Give the key's project access to `AI_MODEL`, or pick another model |
| OpenAI does not offer the model. Check AI_MODEL. | Correct the model name and restart the API |
| OpenAI refused the request, followed by OpenAI's reason | Usually a model without image input or structured outputs; pick one that has both |
| The OpenAI account has no remaining quota. | Add credit to the OpenAI account |
| OpenAI is rate limiting requests. | Retried automatically; try again later if it persists |
| OpenAI had an internal error. | Retried automatically; try again later |
| OpenAI did not answer in time. | Retried automatically; try again |
| Could not reach OpenAI. | Check the API container's outbound network |
| OpenAI request failed. | Retried automatically when OpenAI reports a timeout, a conflict or a server error; otherwise check the API logs |
| OpenAI refused to analyze this listing. | The model declined the images; try again or another model |
| The model ran out of output tokens. | Try again; a model with a larger output limit avoids it |
| OpenAI filtered the response. | The images tripped OpenAI's content filter |
| OpenAI returned an unreadable response. | Retried automatically; try again |
| The model returned observations that do not match the schema. | Retried automatically; a model with structured outputs avoids it |
| The analysis did not finish. Try again. | The run took more than 10 minutes, usually because the API restarted; start it again |
| The analysis could not be queued. Try again. | Redis did not accept the job; check the Redis container, then start it again |
| This listing has no icon or screenshots to analyze yet. Refresh the app, then try again. | Wait for the daily pipeline or refresh the app |
