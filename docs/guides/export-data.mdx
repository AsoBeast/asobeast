Both the keyword monitor and the rankings view export the table you are looking at, with the filters you have applied, as a CSV file. The app overview and the rankings view also print as a report, which is the quickest way to share a view with someone who has no account.

## Export keywords to CSV

The export writes one row per tracked keyword, named `keywords-<appId>-<date>.csv`.

| Column group | Columns |
| --- | --- |
| Identity | `keyword`, `source`, `active`, `bucket`, `relevance` |
| Position | `position`, `delta1d`, `delta7d`, `volatility` |
| Scores | `popularity`, `difficulty`, `opportunity` |
| Provenance | `scoredAt`, `scoringSource`, `formulaVersion`, `confidence`, `capturedAt` |
| Evidence | `suggestReach`, `serpFlags` separated by spaces, `officialPopularity`, `scoreOutdated` |
| Caveat | `scoreComparability` |

The provenance columns travel with the scores on purpose. A spreadsheet that carries `formulaVersion` and `confidence` can still be audited months later, while one that carries only a number cannot.

The last column repeats, on every row, that App Store and Google Play scores use different public signals and are not directly comparable. That caveat is easy to lose once data leaves the product, so it is written into the file. See [App Store and Google Play](/concepts/stores).

`position` is formatted the same way the table shows it, so an unranked keyword exports as `>200` rather than as an empty cell or a zero. See [Positions and rank depth](/concepts/positions).

## Export rankings to CSV

The rankings view exports the charted window as one row per date and one column per keyword, named `rankings-<appId>-<from>-<to>.csv`.

## Print a report or save it as PDF

The app overview and the rankings view print as a report. Select **Print report**, on the overview next to the snapshot facts and on the rankings view next to **Export CSV**, or use the browser's print command. To get a file, choose **Save as PDF** as the destination.

The printout leaves out the navigation, the header controls, banners and notifications, and every button. It opens with the app name, its store and home storefront, the page, each range the charts show, and the UTC date it was printed. Range pickers print as the range they are set to, so set them before you print.

| On screen | On paper |
| --- | --- |
| Dark theme | Always the light theme |
| Range tabs | The selected range, such as `Last 30 days` |
| Charts side by side | One chart per row, scaled to the page width |
| Grade colours | The colour and the grade word, such as `3 strong` |

Charts keep the shape they had on screen and shrink to fit the paper, so a chart drawn across a wide window prints with smaller text. For larger chart text, print the overview in landscape or from a narrower window. Grade colours, badges and chart legends print even with background graphics turned off.

Other pages print without the navigation and in the light theme, but without a report layout.

## Are the files safe to open?

Yes. Every field that begins with `=`, `+`, `-`, `@`, a tab or a carriage return is prefixed with an apostrophe before it is written, so a spreadsheet treats it as text rather than as a formula. Fields containing quotes, commas or newlines are quoted and escaped, and the file carries a byte order mark so spreadsheets read it as UTF-8.

## Use the API instead

For anything scripted, read the API rather than parsing an export. It returns typed JSON and it does not depend on which filters happened to be applied in a browser. See [asobeast API](/api-reference/introduction).
