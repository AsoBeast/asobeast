The keyword monitor, the rankings view, the competitor list and the comparison matrix on the competitors page, the reviews list and the top 10 sheet each export a CSV file that follows the filters you have applied. `<date>` in a file name is the UTC day of the export. The app overview and the rankings view also print as a report, which is the quickest way to share a view with someone who has no account.

## Export keywords to CSV

The export writes one row per tracked keyword, named `keywords-<appId>-<date>.csv`.

| Column group | Columns |
| --- | --- |
| Identity | `keyword`, `source`, `active`, `bucket`, `relevance` |
| Position | `position`, `delta1d`, `delta7d`, `volatility` |
| Scores | `popularity`, `difficulty`, `opportunity` |
| Provenance | `scoredAt`, `scoringSource`, `formulaVersion`, `confidence`, `capturedAt` |
| Evidence | `suggestReach`, `serpFlags` separated by spaces, `officialPopularity`, `scoreOutdated` |
| Caveat | `scoreComparability` |
| Owner notes | `tags` separated by semicolons, `note` |

The provenance columns travel with the scores on purpose. A spreadsheet that carries `formulaVersion` and `confidence` can still be audited months later, while one that carries only a number cannot.

The `scoreComparability` column repeats, on every row, that App Store and Google Play scores use different public signals and are not directly comparable. That caveat is easy to lose once data leaves the product, so it is written into the file. See [App Store and Google Play](/concepts/stores).

`position` is formatted the same way the table shows it, so an unranked keyword exports as `>200` rather than as an empty cell or a zero. See [Positions and rank depth](/concepts/positions).

## Export rankings to CSV

The rankings view exports the charted window as one row per date and one column per keyword, named `rankings-<appId>-<from>-<to>-<date>.csv`, where `<from>` and `<to>` are the first and last day of the window.

## Export competitors to CSV

The competitors page exports one row per tracked competitor from its latest snapshot, named `competitors-<appId>-<date>.csv`. Your own app is not in the file.

| Column | What it holds |
| --- | --- |
| `competitor` | The competitor's name |
| `store` | `APP_STORE` or `GOOGLE_PLAY` |
| `title`, `subtitle`, `summary` | The listing text of the latest snapshot, where `summary` is the Google Play short description |
| `rating`, `ratings` | The average rating, unrounded, and the number of ratings |
| `installs` | The install count |
| `price` | The price, `0` for a free app |
| `version` | The latest version |
| `capturedAt` | When the snapshot was taken, in UTC |

A column the store does not publish stays empty: `subtitle` on Google Play, `summary` and `installs` on the App Store. See [App Store and Google Play](/concepts/stores).

## Export the keyword comparison to CSV

The comparison matrix exports the rows it shows, in the order shown, after the search and the result filter. The file is named `keyword-comparison-<appId>-<date>.csv`, or `keyword-gaps-<appId>-<date>.csv` when **only gaps** is on, and then it holds the gap rows alone.

| Column | What it holds |
| --- | --- |
| `keyword` | The tracked phrase |
| `popularity`, `difficulty` | The scores on the 0 to 100 scale the matrix shows, empty when unscored |
| `you` | Your position |
| One column per competitor | That competitor's position, headed by its name |
| `result` | `winning`, `losing` or `tied`, empty when nobody ranks |
| `gap` | `true` on the rows the matrix marks as a gap, otherwise `false` |

Positions are written the way the matrix shows them, so an app that does not rank exports as `>200`. Two competitors with the same name get `(2)`, `(3)` after the name so every column header stays unique, and a competitor without a name is headed `Competitor`. What winning, losing, tied and a gap mean is explained in [Read the comparison matrix](/guides/competitors#read-the-comparison-matrix).

## Export reviews to CSV

The reviews list exports the newest 200 reviews that match the star and version filters, newest first, named `reviews-<appId>-<date>.csv`. The reviews endpoint returns at most 200 reviews in one request and does not page, so older reviews are not in the file. When more reviews match, a notice after the download says how many the file holds. Narrow the filters to reach a different set, for example one version at a time.

| Column | What it holds |
| --- | --- |
| `reviewedAt` | The review's date in UTC, empty when the store sent none |
| `score` | 1 to 5 stars |
| `title`, `text` | The review, with `title` empty when it has none |
| `version` | The app version the store attached to the review, when it sent one |
| `author` | The reviewer's display name |
| `reviewId` | The store's own id for the review |

## Export a SERP snapshot to CSV

The top 10 sheet on the keyword monitor exports the snapshot it shows, one row per result, named `serp-<appId>-<keywordId>-<captured>-<date>.csv`, where `<captured>` is the day the snapshot was taken.

| Column | What it holds |
| --- | --- |
| `keyword`, `capturedOn` | The phrase and the snapshot's day, repeated on every row |
| `position` | 1 to 10 |
| `app`, `developer` | The result's title and developer |
| `rating`, `ratings` | Its average rating and rating count |
| `role` | `you`, `competitor` for an app tracked as a competitor in the workspace, as the sheet's badge shows, or `other` |
| `storeAppId` | The store's id for the app |

`ratings` stays empty for Google Play keywords, whose search results carry no rating counts. See [App Store and Google Play](/concepts/stores).

## Print a report or save it as PDF

The app overview and the rankings view print as a report. Select **Print report**, on the overview next to the snapshot facts and on the rankings view next to **Export CSV**, or use the browser's print command. To get a file, choose **Save as PDF** as the destination.

The printout leaves out the navigation, the header controls, banners and notifications, and every button. The keywords charted on the rankings view print as a row of labels with their colours. It opens with the app name, its store and home storefront, the page, each range the charts show, and the UTC date it was printed. Range pickers print as the range they are set to, so set them before you print.

| On screen | On paper |
| --- | --- |
| Dark theme | Always the light theme |
| Range tabs | The selected range, such as `Last 30 days` |
| Charts side by side | One chart per row, scaled to the page width |
| Grade colours | The colour and the grade word, such as `3 strong` |

Charts keep the shape they had on screen and shrink to fit the paper, so a chart drawn across a wide window prints with smaller text. For larger chart text, print the overview in landscape or from a narrower window. Grade colours, badges and chart legends print even with background graphics turned off.

Other pages print without the navigation and in the light theme, but without a report layout.

## Are the files safe to open?

Yes. Every field that begins with `=`, `+`, `-`, `@`, a tab or a carriage return is prefixed with an apostrophe before it is written, so a spreadsheet treats it as text rather than as a formula. Fields containing quotes, commas or newlines are quoted and escaped, and the file carries a byte order mark so spreadsheets read it as UTF-8.

## Use the API instead

For anything scripted, read the API rather than parsing an export. It returns typed JSON and it does not depend on which filters happened to be applied in a browser. See [asobeast API](/api-reference/introduction).
