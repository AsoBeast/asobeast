# MCP rules

## Shared code rule 7: `@asobeast/mcp-tools` owns the tool catalog

`MCP_TOOLS` (reads) and `MCP_WRITE_TOOLS` (writes) are the single definition of the MCP surface: name, title, description, `z.object` input schema, and the route each tool wraps (a `GET` for a read tool; a method, a path and a JSON body for a write tool, with its destructive, idempotent and open world hints and the `outcome` that shapes what an agent reads back). `toolsFor(scope)` decides what a connection lists, `requestOf` turns a tool into an HTTP request, `annotationsOf` produces its annotations, and both transports call those and nothing else: `apps/mcp/src/tools/` for stdio and `apps/api/src/mcp/remote-tools.ts` for `POST /mcp`. It depends on `@asobeast/shared` and `zod` and nothing else, and `parity.test.ts` proves the registration has not drifted.

## Domain rule 10: Both MCP surfaces are mandatory-token surfaces, read-only unless the token is write scoped

`apps/mcp` is the stdio binary and authenticates like any other client: it sends `ASOBEAST_API_TOKEN` (`asob_…`) as a Bearer header on every request, and a boot-time preflight (`/auth/me`) exits non-zero against a missing or invalid token or an unentitled instance and reads the token's `tokenScope`. `apps/api/src/mcp/` is the remote endpoint: `POST /mcp` takes the same `asob_` token through `AuthGuard`, refuses a session cookie with 401, and dispatches each tool in process through `InProcessGateway.send` (a method, a URL and an optional JSON body) rather than over a socket, so the inner route's own guards, `StorableTextPipe`, `ValidationPipe`, plan write budget and quota run unchanged. Every tool in `MCP_TOOLS` is a `GET` annotated `readOnlyHint: true` and must stay so: **a write tool never joins that list**. The seven tools in `MCP_WRITE_TOOLS` (`track_keywords`, `untrack_keyword`, `add_competitor`, `remove_competitor`, `set_action_status`, `add_annotation`, `delete_annotation`) are listed only to a token whose scope is `write`: `McpBridge.admit` attaches that scope as `req.auth`, the factory reads it from `authInfo`, and stdio reads it from the preflight; anything but an explicit `write` lists reads only. The listing is a convenience, the authority is `TokenScopeGuard` on the inner route, so a read token that named a write tool would still get 403. A write tool wraps an existing route, never a new one or parallel logic, declares honest hints (`destructiveHint` for a delete, `openWorldHint` for anything that reaches the store), and returns a slim `outcome` rather than the route's whole answer. A failed write with status 0 or 5xx, or a 2xx answer the client could not read, says the change may or may not have been applied. On stdio the JSON-RPC stream owns stdout, so all diagnostics go to stderr and the token is never logged. `POST /mcp` draws the plan's `mcpRequestsPerMinute` budget one unit per JSON-RPC message in the body (`messageCountOf`), so a batch of n costs n through one `INCRBY` and is refused whole with the rate limit `429` when the window cannot cover it, uncounted when n exceeds the whole budget because no window could ever serve it; a single request of any kind still costs one. **`packages/mcp-tools` must never import an MCP SDK package**: it is the single definition both transports read, and an SDK import there would put a bundled type identity between two packages that must stay interchangeable.
