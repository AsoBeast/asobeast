# Keyword rules

### Domain rule 2: The iOS keyword field (100 chars) is private, and there is one per App Store localization, edited in one place

It never appears on the store page and cannot be scraped; the owner types it on the metadata page (source `KEYWORD_FIELD`). It is counted in characters, the way App Store Connect counts it, with `keywordFieldChars` against `KEYWORD_FIELD_CHAR_LIMIT`, the same `countChars` the title and subtitle use, so a letter such as ą or a Chinese, Japanese or Korean character counts once. The 100-character cap on one tracked phrase (`TRACKED_KEYWORD_CHAR_LIMIT`) is counted in characters too: `checkKeywordText` and the listing combinations use `countChars`, and the `track_keywords` tool relies on zod, which measures a string's `max` in code points. `countChars` counts Unicode code points and `truncateChars` cuts by the same unit, both in `packages/shared/src/aso/limits.ts`, so a Han character outside the Basic Multilingual Plane such as 𠮷 counts once and an emoji sequence counts by its parts; a store field is never measured with `String.length` or cut with `String.slice`, and never counted in grapheme clusters, because `Intl.Segmenter` answers differently in Node, Chromium and WebKit. `countMaxLengthChars` stays the count `class-validator`'s `MaxLength` uses and is not a store limit. `KeywordField` (tenant owned, RLS, `@@id([appId, localization])`, explicit localization tags, never `NULL`) stores the normalized phrases in submission order, and is the only source of truth: a tracked keyword is in a keyword field when a saved field of a localization its market reads (`keywordFieldLocalizations` in `@asobeast/shared`, which answers English (U.K.) for a home country an older release imported without checking it is a storefront) holds its normalized text, which `indexKeywordFields` in `keywords/keyword-field-index.ts` answers and `reportedSource` reports. Never store membership on `TrackedKeyword` again. **What an app ships is `AppLocalization`** (tenant owned, RLS, `@@id([appId, localization])`, `origin` `manual` or `detected` as text validated in code): the home localization (`homeLocalization`, never stored, never removable), plus its rows, plus any localization with a saved field, joined in one place, `AppLocalizationsService.list`. **I-FIELD:** a non empty save of a localization other than the home one upserts its row as `manual` inside the save transaction through `recordAppLocalizations`, never downgrading `detected`; an emptied field keeps its row and only `DELETE /apps/{id}/localizations/{localization}` removes one. **Every save goes through `KeywordFieldWriter`**, the one transaction (`QuotaService.admitKeywordMarkets` first, which takes the quota lock, then the per-app field lock) that stores the phrases, records the localization, tracks every phrase in every market of `trackIn`, and stops tracking a dropped phrase as `KEYWORD_FIELD` in every market that reads the localization unless another field read there holds it; `remove` is the same transaction with an empty field and the row deleted. `trackIn` is a subset of the app's markets (`appMarkets`: home first, then every country in which the app tracks a keyword, active or paused) whose storefront reads the localization (`trackInError`), and may be empty; untracking a keyword never edits a field. The pure rules live in `keywords/localization-markets.ts` (`readsKeywordField`, `readerRole`, `readersOf`), `keyword-field-save-plan.ts` and `market-keyword-fields.ts`; a preview computes them and writes nothing. The editor exists on the metadata page only. The keywords page reports through `GET /apps/{id}/keyword-fields/market` and never writes a field, and the words read twice and split phrases it shows are diagnostics that never reach coverage, the audit or an Action Center rule. `GET` and `PUT /apps/{id}/keyword-field` without a query still mean the home storefront's default localization, which is where the upgrade put every field saved before; `PUT` calls the writer with `trackIn = [country]` and answers as before. **The import of the fields from App Store Connect is a per-app, owner-only opt-in through a signed-in session.** `POST /apps/{id}/keyword-fields/import` and `DELETE` on the same path are `@SessionOnly()` with `OwnerGuard`; `KeywordFieldImportController` hands to `KeywordFieldImportService` (store-connect), whose start upserts the app's `KeywordFieldSync` row through `AppLocalizationsService.startImport`, enqueues the sync through the store reports queue and removes the row again when the enqueue fails, and whose stop runs `stopImport`; the start answers 409 unless the state is `available`, the stop 404 when nothing follows, and a stop wins over a run in flight because the sync writes the existing row only (`updateMany`) and every field write checks the row is still following first. The localizations result carries `storeImport` (`STORE_IMPORT_STATES`: `unavailable` without a console key, `available`, `following`, `paused` while the key is refused) and `importStateOf` derives it from the row plus the active connection, so `storeManaged` is true only while the row exists and the key works, and a rejected key or a removed `STORE_CONNECT_ENCRYPTION_KEY` hands the fields back editable (`refuseManagedField` still refuses a save while `following`); `importStateOf` reads the connection row itself because `AppLocalizationsService` cannot depend on the store connect module without a cycle. The sync's `at` read time is null until the first read lands, and a skipped read records `lastError` instead. The sync (`AscKeywordFieldSync`, `keywords/keyword-field-managed.ts`) runs after every report download for the apps holding a row: it stores what App Store Connect serves for each served localization through the writer with `trackIn` limited to the markets that read that localization as their default, removes a stored localization the store stopped serving (the home localization excepted), skips an unchanged import, and a 429 from the store records `rateLimited` on the report summary instead of failing it. `ListingCaptureService.releaseChangedFields` enqueues the sync only when the row exists and the listing version changed.

### Domain rule 15: A keyword import is validated by the server and only adds or resumes keywords

The browser reads the file (`apps/web/src/lib/csv-import/`: decode, tokenize, header aliases, column mapping, the country cell, the scope) and sends `KeywordImportRow[]`; it applies no keyword rule and decides no status. It does narrow a file to the app and store it is imported into when the file names them (`scope.ts`: an `App Id`, `App Name`, `Platform` or `Store` column) and says how many rows it left out, because a combined export of several apps must not become the keywords of one. `POST /apps/{id}/keywords/import/preview` and `POST /apps/{id}/keywords/import` run one plan (`classifyImportRows`, then `planImport`, both pure) and answer a status per row: `new`, `resume`, `tracked`, `duplicate`, `invalid`, `overQuota`. A row is held to the same limits as `PATCH /apps/{id}/keywords/{keywordId}`, measured the same way, so a note is counted with `countMaxLengthChars` like the DTO's `MaxLength`, never with `String.length`. The preview is `@RateLimitClass('read')` and `@ReadOnlyEndpoint()` and writes nothing. The import is a write: it tracks `new` and `resume` rows as `MANUAL` with their tags and note inside one `QuotaService.admitKeywordMarkets` transaction, never changes the tags or note of a keyword the app already tracks and changes a paused one only by resuming it, skips rows over the plan's keyword room instead of failing them, and leaves the admission as the safety net for a race (`403`, nothing written). Its answer reports the plan in `summary` and `results`, what this request actually wrote in `imported`, and `quota.used` read after the write. One request carries at most `KEYWORD_IMPORT_LIMIT` (500) rows so it stays inside the 100 KB body limit. The web splits a longer file into parts of at most that many rows and 96,000 bytes (`importParts` in `lib/keyword-import.ts`) and previews and imports one part at a time, previewing the next only after the one before it was imported, so every preview is the server's answer against what is already tracked; it refuses only a single row too large for a request. A change to the columns, the app or the market starts again from the first part, and a part the server finds nothing to import in offers **Skip to part N** instead, so an imported part never blocks the ones after it. The daily store requests an import adds come from `requestsPerJob` and travel in `cost`, never copied into the web. A phrase another app of the workspace already tracks opens no keyword market, because `countKeywordMarkets` counts distinct keyword rows. The keyword CSV export ends with `country`, so a file always names its storefront, and the importer undoes the apostrophe `escapeField` puts before a formula-like cell.

### Domain rule 22: The keyword breakdown judges with coverage's own functions and never guesses a listing

`GET /apps/{id}/keywords/{keywordId}/breakdown` (`KeywordBreakdownService`) reads stored rows only and reaches no store. It builds each app's surfaces with `judgingSurfaces`, the primary app with its non empty saved fields and a competitor with none, judges the phrase with `coversKeyword` so it never disagrees with the coverage table, and reports an accent folded word (`searchKey`) as `folded` without counting it. Each localization is judged alone, because App Store search never combines words of two localizations. A localization the market searches that has not been captured for an app is listed in `unread`, never borrowed from another storefront. `ranking: null` is never checked, `position: null` is checked and not found. A competitor note is a pure rule in `keyword-breakdown-insights.ts` with named thresholds (`RATINGS_GAP_FACTOR`, `RATINGS_MIN_GAP`, `SETTLING_DAYS`); the ratings rule compares two ratings only when both come from the keyword's market listing. The web renders the server's `segments` and decides no match itself, and reads the breakdown with `useQuery` under `appKeys.compareRoot`, so a keyword change refreshes it and a failure never replaces the page. The MCP read tool `keyword_breakdown` wraps the same route. The keyword list route (`GET /apps/{id}/keywords`) also answers `dropStreak` (`keyword-drop-streak.ts`: consecutive checks at which the position got worse, from the last 60 checks the list already reads, null when paused or stale) and, for active keywords, `uncovered` (`judgeKeywordCoverage` in `metadata/keyword-coverage-judge.ts`, the one function both the coverage table and the list call); the web insight badges read these and no other source. It also answers the optional `matchedIn` of each keyword that has a mark (only the controller asks, with `listingMarks`): the keyword text in runs, each word marked with the strongest surface of the keyword's market that holds it (`keywordMarker` in `keywords/keyword-marks.ts`, over the surfaces `keywordSurfaces` answers for coverage, so the same market and every localization it reads, judged by `wordMatch` and located by `markWords` of the breakdown, exact before folded), never by `runsTogether`, which is scoring evidence, and never in the description; whenever coverage says a surface covers the keyword every word is marked, and the web draws the segments and decides no match. The competitor gap lists answer on `GET /apps/{id}/competitors/analysis` beside the three older arrays, which never change: `competitor-gap-lists.ts` and `competitor-threats.ts` are pure rules over `KeywordsService.compare` and the last nine days of `KeywordRanking` rows of the app and its comparable competitors (not delisted, not unchecked), with the five thresholds exported from `@asobeast/shared` (`GAP_TOP`, `GAP_YOU_BELOW`, `WINNABLE_COMPETITOR_FROM`, `THREAT_WITHIN`, `THREAT_WINDOW_DAYS`); a threat reads the two apps' rankings and the `overtaken` function of `rank-milestones.ts`, never an alert event, because an event exists only for a workspace that subscribed to it, and a stale check never makes a threat.

### Domain rule 25: A keyword's class is derived at read time by one matcher and only the owner can override it

`KeywordClass` (`ownBrand`, `competitorBrand`, `generic`, `@asobeast/shared`) is answered on `GET /apps/{id}/keywords` and on the `PATCH` answer only (`listTracked` with `brandFacts`, which `listingFacts` turns into `classOf` through `loadBrandProfile` and `keywordClassifier` in `keywords/keyword-brand-profile.ts`; every other caller leaves the fields off) by `classifyKeyword` (`keywords/keyword-class.ts`) from stored data: a keyword is a brand when it contains the whole brand name of the app (leading words of its home title and of its title in the keyword's market, `brandNameOf` in `keywords/brand-words.ts`, and its developer name without legal suffixes) or of one competitor, or the SERP `brand` flag was raised with no name to match; when the stored page shows that most of the top 10 titles already target the phrase (`GENERIC_SERP_RELEVANCE`) the keyword is generic unless the flag was raised; a competitor name that your own listing of the keyword's market uses, or that `CATEGORY_NAME_COMPETITORS` competitors share (plurals count as the same word), is a category word and never a brand, so a keyword that holds one is generic even when the flag was raised. Everything that splits by brand (insight badges, share of voice, compare two dates, the branded acquisitions split, the country scan) calls that matcher and never re-implements it. The owner's override is `TrackedKeyword.keywordClass`, text validated in code with `isKeywordClass` (an unknown stored value reads as no override), set through `PATCH /apps/{id}/keywords/{keywordId}` (`null` clears it) and answered as `keywordClassSource: 'owner'`; it is not an MCP write tool. The non branded share of voice reads the classes alone through `KeywordsService.keywordClasses` (`keywords/keyword-classes.ts`), which runs the same `classFacts` over the tracked rows, their latest score signals and the brand profile of `listingFacts`, so it never disagrees with the keywords list and skips the rankings, SERP days and acquisitions that list reads.
